# Code-Review und Sicherheitsprüfung 0.6.0

Stand: Zweig zu 0.6.0, Prüfung vom 31.10. und 01.11.2026. Release-Schritte 3 und 4 der [README](../README.md). Geprüft
haben mehrere Modelle, keines davon hat die jeweils geprüfte Korrektur gebaut. Jeder Befund wurde am Code nachgeprüft;
behobene haben einen Regressionstest, vor allem in `test_sicherheit.py`, `test_api.py`, `test_freigabe.py`,
`test_reibung.py` und `skills/web-zugriff/scripts/tests/test_pruefung.py`.

Angreifer: ein fremdes, geklontes Wiki (`wiki.toml`, Karten, SVG, `design.css`, Symlinks, Lauf-Ordner), eine fremde
Webseite im Browser, während `serve` läuft, und eine Webseite, die den Agenten im Container steuert.

## Behoben

Die einzelnen Punkte stehen im [CHANGELOG](../CHANGELOG.md) unter „Sicherheit“. Die schwersten:

- `uv.toml` im Wiki lenkt den Paket-Index um und führt so fremden Code aus (im Versuch bestätigt).
- Skript im Dashboard über Attributlisten, Link-Schemata, SVG und CSS.
- Lesen und Schreiben außerhalb des Projekts über Symlinks, Vorlagen, Manifeste und Pfade der `wiki.toml`.
- Doppelte Host-Köpfe und Schutzfelder im `serve`-Pfad; Freigaben über `--set` und über Schreibweisen des Frontmatters.
- Befehl in der kopierbaren `fundweg`-Zeile aus einer fremden `kandidaten.json`.
- Anhang als Symlink, der einen Schlüssel an den Modellanbieter schickt.
- Agentenangaben im Kopf von `web-recherche`, außerhalb des als unvertrauenswürdig markierten Bereichs.

## Verworfen, mit Grund

| Befund | Grund |
|---|---|
| `rglob` folgt Verzeichnis-Symlinks | Unter Python 3.11, 3.12 und 3.14 im Versuch widerlegt. |
| XML-Entity-Bombe in `api.py` | expat bricht mit „input amplification“ ab, `main` meldet das als Text. |
| Domains wie `nip.io` auf interne Adressen | Der Proxy prüft die aufgelöste Adresse und verbindet mit ihr. |
| `by: human:…` im Fundweg | Herkunftsangabe eines Funds, keine Freigabe. |
| `edit_resets_stable = false` | Lint meldet die verfallene Freigabe als Fehler (`test_abschaltbar_dann_fehler_bei_stable`). |
| Hash großer Dateien ohne Grenze | Nur noch innerhalb des Projekts; dort kein Angriff über die Grenze des Nutzers hinaus. |
| Anbieter-Fehlertexte und Pfade in Meldungen | Eigene angemeldete Sitzung; Keys werden geschwärzt. |
| YAML-Alias-Bombe | Der Lader kennt keine Aliase. |
| Token im Modellkontext, GET ohne Origin | Der Token steht nicht im Kontext; GET ändert nichts, POST verlangt Origin. |
| `capture --file`, `dashboard --out`, `WIKI_ACTOR`, Wettläufe desselben Nutzers | Eingaben der Person selbst, keine Grenze. |
| `is_timestamp` im letzten Diff nicht definiert | Steht außerhalb des Diffs im Kern, also kein `NameError`. |
| Feste Liste der Font-Typen in `design.css` weist alte Untertypen ab | Gewollt: Unbekanntes wird abgewiesen, die Meldung nennt den Grund. |

## Bewusste Grenzen

- Der Guard hängt an Write und Edit. Bash sieht er nicht, er ist Schutz gegen Versehen, keine Sandbox.
- Eine Freigabe in einer fremden Karte lässt sich mit Hash nachbauen, solange `signed_human` aus ist.
- Die `wiki.toml` legt Datenklasse und Rollen selbst fest, Rechte für die KI-Auswertung stammen aus demselben Wiki.

## Für 0.7.0 zurückgestellt

Nur wirksam, wenn jemand das Ergebnis rendert, oder als Folge einer Änderung, die auch Bash könnte:

- `web-recherche`: HTML-Reste setzen sich zu Tags zusammen (`<<b>script>`); URL-Formen mit `\@`, Entities und weiteren
  Schemata entgehen der Prüfung. Die Datei wird als Text gelesen (Restrisiko in der README des Skripts).
- Der Guard schützt die `wiki.toml` nicht, und eine zweite `wiki.toml` im Unterordner gilt für alles darunter.
- Ein Edit, dessen `old_string` der Hook anders auflöst als das Werkzeug, bleibt ungesehen (Vermutung).
- Steuerzeichen aus der `wiki.toml` in der Ausgabe von `rollen.py`; Terminal-Wirkung je nach Terminal.
- Lint-Meldungen mit Kartentext in der Stop-Rückgabe: Der Hook nennt sie Daten, kürzt sie aber nicht.
- `http_json` folgt Weiterleitungen ohne Host-Prüfung; das Schreiben von Karten läuft nicht über `replace_file`.
- Eine Untergrenze für die Datenklasse, die eine fremde `wiki.toml` nicht unterschreiten kann.
- `api.py archivieren` überspringt Symlinks im Lauf-Ordner, ohne das zu melden; das Archiv kann dann unvollständig sein.
